# 5分登壇台本：PHPで買い物かごの合計を作る

**登壇枠全体が5分**の想定です。導入・デモ・解説・締めを含め、ライブデモは約3分20秒に収めます。学習者に一度予測と試行をしてもらい、意図的な誤答をヒントで直し、関数とテストで終える構成です。

## 登壇前の準備

- プロジェクトを開き、エージェント選択で **PHP Learning Coach** を選ぶ。PHP学習の相談に応じて `php-learning-coach` Skillが学習手順を担う。
- PHP 8.3.x のCLIを事前に確認する。発表中にインストールやバージョン確認はしない。
- エディターとターミナルを並べる。`shopping-total.php` を次の未完成状態で開き、完成コードは学習者の試行後まで隠す。
- 登壇者が学習者役を担当し、`ask_user` の入力には用意した短い返答をすぐに返す。聴衆全員の回答を待つ形式にはしない。
- エージェントがPHPを実行したように見せず、実行コマンドは登壇者がターミナルで実行する。

```php
<?php
$prices = [120, 250, 80];
$total = 0;

foreach ($prices as $price) {
    // ここに合計を更新する行を書く
}

echo $total . PHP_EOL;
```

## 学習者と課題

- **初期知識:** PHP初心者。算数の足し算は分かる。ターミナルでPHPを実行できる。
- **学習目標:** 整数価格の配列を `foreach` で処理し、合計を返す関数を作って結果をテストする。
- **仕様:** `[120, 250, 80]` の合計は `450`。`[100, 50]` の合計は `150`。空配列の合計は `0`。
- **学ぶこと:** 配列、`foreach`、累積、関数の引数と `return`。フレームワークや型宣言は扱わない。

## 発表進行と会話台本（合計5分）

### 0:00–0:20 — 導入

**登壇者**

> 生成AIに答えをすぐ書かせるのではなく、学習者が予想し、試し、間違いから学べるようにする方法を、PHPの小さな例で紹介します。

**操作:** エージェント選択から **PHP Learning Coach** を選ぶ。エージェントは対話のコーチ役、Skillは学習の進め方を担当する、と短く紹介する。

### 0:20–0:45 — 依頼と予想

**学習者（最初の問い）**

> PHPは初めてです。PHP 8.3をターミナルで実行できます。買い物かごの3品 `[120, 250, 80]` の合計を出したいので、考え方を教えてください。

**エージェント（ask_user）**

> まずコードを書く前に、期待する合計はいくらでしょう？

**学習者**

> 450です。

**エージェント（ask_user）**

> `foreach ($prices as $price)` なら、`$price` はどの値を順番に受け取ると思いますか？

**学習者**

> 120、250、80です。

**登壇者の補足**

> 目標と初学者であることは最初の問いに含まれているので、エージェントは聞き直しません。

### 0:45–1:40 — 意図的な誤答と段階的ヒント

**エージェント（ask_user）**

> 合計を0から始めるとして、ループ内で `$total` を更新する行をどう書きますか？

**学習者（意図的な誤答）**

> 数字をつなげれば合計になると思います。

```php
$total = $total . $price;
```

**エージェント（ask_user）**

> まだ実行せずに予想しましょう。最初の周回では `$total` が `0`、`$price` が `120` です。この式の結果は `120` と `0120` のどちらでしょう？

**学習者**

> `120` だと思います。`.` は足し算のように見えます。

**エージェント（段階的ヒント）**

> PHPでは `.` は文字列をつなぎます。最初は `"0"` と `"120"` がつながるので `0120` です。残りも同じ処理だと、最後の表示はどうなるでしょう？

**学習者**

> `012025080` です。

**操作:** 未完成ファイルにその一行を入れ、ターミナルで実行する。

```text
php -l shopping-total.php
php shopping-total.php
```

**想定出力**

```text
No syntax errors detected in shopping-total.php
012025080
```

**エージェント（ask_user）**

> `php -l` は構文を確認しますが、計算の意味までは確認しません。数値を足す演算子に直すなら、何を使いますか？

**学習者**

> `+` です。`$total = $total + $price;` に直します。

### 1:40–2:15 — 予測して修正を検証

**エージェント（ask_user）**

> 直した場合、ループ後の `$total` はいくらになると予測しますか？

**学習者**

> 450です。

**操作:** 学習者役が一行を修正し、構文確認と実行を行う。

```text
php -l shopping-total.php
php shopping-total.php
```

**想定出力**

```text
No syntax errors detected in shopping-total.php
450
```

**エージェント**

> その通りです。毎回の値で上書きせず、前回までの合計に今回の価格を足して保存しました。

### 2:15–2:50 — 関数化とテスト

**エージェント（ask_user）**

> この計算を `calculateTotal($prices)` という関数にします。呼び出し側に何を返すとよいでしょう？

**学習者**

> 最後の `$total` を `return` します。

**エージェント**

> ループを試して関数の戻り値も選べたので、全体とテストを確認しましょう。

**エージェント（完成例。学習者の試行後に表示）**

```php
<?php
function calculateTotal($prices)
{
    $total = 0;

    foreach ($prices as $price) {
        $total = $total + $price;
    }

    return $total;
}

if (calculateTotal([120, 250, 80]) !== 450) {
    fwrite(STDERR, "FAIL: 3 items\n");
    exit(1);
}

if (calculateTotal([100, 50]) !== 150) {
    fwrite(STDERR, "FAIL: 2 items\n");
    exit(1);
}

if (calculateTotal([]) !== 0) {
    fwrite(STDERR, "FAIL: empty list\n");
    exit(1);
}

echo "OK: 3 tests\n";
```

**操作:** ファイルを保存して `php -l shopping-total.php` と `php shopping-total.php` を実行する。想定出力は `No syntax errors detected in shopping-total.php` と `OK: 3 tests`。

### 2:50–3:20 — 公式資料と振り返り

**エージェント**

> PHP公式マニュアルでは、[算術演算子](https://www.php.net/manual/ja/language.operators.arithmetic.php) の `+` が数値を足すこと、[文字列演算子](https://www.php.net/manual/ja/language.operators.string.php) の `.` が文字列を連結することを確認できます。`foreach` では値が一つずつ取り出されること、[関数](https://www.php.net/manual/ja/language.functions.php) では引数と `return` を確認できます。

**エージェント（ask_user）**

> 最初の式で450にならなかった理由を、一言で説明できますか？

**学習者**

> `.` は数を足さず文字列をつなぐからです。合計には `+` を使います。

## 成功条件と登壇メモ

- 5分枠全体の配分は、導入20秒、デモ3分、解説1分、まとめ40秒。
- エージェントは既知の初心者レベルや目標を聞き直さず、最初の問いを小さな予測に分ける。
- 学習者が `.` の誤りを実行し、`012025080` と450の違いを自分の言葉で説明する。
- 完成コードは学習者がループを試してから示し、関数の戻り値を考えた後でテストを実行する。
- `php -l` は構文確認、実行は出力、3ケースの比較は期待結果の確認として説明を区別する。
